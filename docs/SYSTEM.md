# Reusable banner system

## Product path

Choose market → upload original campaign image/logo/font → enter copy once → formats update automatically → review every format → edit exceptions → export an exact-size set. Blueprints is a library of layout diagrams for every market, including BANNER1 and BANNER2, with a full structural blueprint editor and a quick fade-only dialog. Campaign text, images, layers and timing are edited in Studio and saved to the selected campaign banner.

## Implementation boundaries

The studio uses a charcoal theme with Higgsfield lime (`#D1FE17`) for primary actions and selection states, neutral panels, and muted teal static-format badges. The primary color was sampled from the [Higgsfield](https://higgsfield.ai/) sign-up button on 27 September 2026. A compact tool rail keeps navigation available; desktop campaign content sits to the right of the format collection, and mobile moves it below the previews. Artboards can be searched by dimensions/name and filtered by static/animated output. The canvas editor, timeline, inspector and dialogs share the same interface palette; Konva selection overlays resolve the CSS theme tokens. These interface colors do not alter campaign artwork or exports. Layout direction references: [Hugging Face](https://huggingface.co/) and [Magnific](https://www.magnific.com/).

- React and Vite, plain JavaScript and JSX, JSDoc on core contracts.
- `src/app/`: React Router 8.4.0 routes, workspace provider and navigation configuration. Campaign, blueprints and assets pages render through the shared layout's `Outlet`; the lazy banner and blueprint editors use full-screen routes.
- `src/layouts/` and `src/pages/`: persistent navigation shell, page spacing and individual route compositions. The active market is stored in the URL query string; direct editor URLs resolve their own market from the banner entry.
- `src/components/ui/`: reusable buttons, inputs, labeled fields, cards/info cards, titles, feedback and dialogs. Feature components use these primitives; they do not own storage or rendering contracts. See [the component guide](UI-COMPONENTS.md).
- `src/hooks/useWorkspaceController.js`: shared campaign, market, blueprint and export actions; `useProject.js` manages local persistence. `src/styles/tokens.css` holds interface theme tokens.
- `src/data/`: market defaults, the Banner 3 layout table and common factories. Dimensions are data; adding a market or a size does not require a renderer branch.
- `src/core/schema.js`: runtime-validated blueprint contract with bounded dimensions, unique layer/scene IDs, valid source bindings and legal timing.
- `src/core/render.js`: deterministic Canvas 2D renderer, text fit/glow, original-image crop/focal point, opacity and directional fade, shared by preview, editor and export.
- `src/core/image-position.js`: image cover geometry and bounded photo panning inside a fixed frame/fade, including rotated frames and reference crop regions.
- `src/core/fade-mesh.js`: a normalized 2–16-point fade boundary (16 by default), presets, softness, direction mapping and bounded cached rendering. Shared by Canvas output and editing overlays; original images are preserved. See the [fade curve contract](BLUEPRINT-SPEC.md#editable-fade-curve).
- `src/core/text-fit.js`: per-format automatic balanced rows, single-line or manual wrapping, bounded font fitting and vertical alignment, shared by every output.
- `src/core/text-layout.js`: available-space suggestions around co-visible layers and image fades; considers all parts and crossfade neighbours without modifying other layers.
- `src/core/auto-layout.js` and `src/hooks/useAutoArrange.js`: automatic campaign composition on text/asset changes. The saved design is kept whenever the copy stays readable in it; otherwise copy reflows within its designed width, then the free width, and the photo frame is resized only as a last resort. A saved derived snapshot feeds the existing preview/export pipeline; the saved automatic-arrangement preference and Arrange now action control it. `src/core/automation-state.js` reports per-banner results (Design kept, Copy reflowed, Photo resized, Blueprint boxes, Edited, Out of date) for the Studio artboard badges and the canvas status chip. A per-market copy hierarchy (`src/data/text-hierarchy.js`, stored on the campaign) caps the smaller copy after arrangement; Hold to compare (D) shows saved designs in place of arrangements.
- `src/core/review.js`: the full review report used by Studio, the editor and export. It adds CTA edge-contrast and detected-face crop/coverage checks to `qualityReport`. `src/core/export.js` reduces GIF palette and in-between frames to meet size limits without changing total timing.
- `src/core/timeline.js`: pure scene/time evaluation. Per-scene durations and per-layer visibility, start/end, fade-in/out and movement. Logo/legal can remain present across scenes.
- `src/components/editor/CanvasEditor.jsx`: Konva interaction surface over the same renderer, with live layer movement, eight resize anchors and a round rotation handle. Controls have room outside the artwork edge; X/Y/rotation numeric fields are removed. Arrow keys nudge by one native pixel, Shift by ten. Each pointer gesture is one undo step. Width/height and opacity remain in the inspector. The canvas never becomes the saved data model.
- `src/core/export.js`: PNG/JPEG/WebP at blueprint dimensions, GIF samples from the same timeline, ZIP with provenance and quality report.
- `src/core/image-analysis.js`: locally bundled, lazy OpenCV.js for image luminance and edge/blur analysis, and the per-cell brightness/detail grid of the campaign photo. Releases Mats; does not run during normal rendering.
- AI arrangement (Studio **Arrange now**): `src/core/studio-ai.js` analyzes the rendered campaign photo once (OpenCV grid, BiRefNet subject map, PaddleOCR text printed in the photo, Florence-2 objects) and stores it as `campaign.photoAnalysis` (`src/core/photo-analysis.js`). `src/core/ai-arrange.js` then asks Qwen3-VL for PosterO-style layouts (`services/vision/layout.py`; layout trees in `src/core/layout-tree.js`, nearest references as in-context examples) and, for every banner, scores the saved design, the nearest reference scaled to the size and each model proposal with the same deterministic checks (`layoutScore`, subject crop, photo readability, closeness to the nearest reference). The cheapest wins and is stored as `banner.aiLayout`; later automatic passes refit copy from it. Missing models fall back to design and reference candidates, so rendering never depends on AI. Blueprint finished-banner import uses Qwen3-VL to name each PaddleOCR line's role (rule-based roles remain the fallback), so a new reference becomes a blueprint that later serves as an example and reference candidate. New sizes and new markets are seeded from the nearest reference shape (`seedBlueprint`) instead of the proportional factory, which remains only for the built-in seeds and when no reference exists. Copy that cannot fit at its minimum size is listed under **Copy fit**; Qwen3-VL suggests shorter versions and an approved one applies to that size only (`campaign.copyFits`, shared with Create).
- `src/core/storage.js`: IndexedDB project snapshots and immutable uploaded blobs, with content-hashed identities. No server account required.

## Studio artboard workspace

Studio opens directly onto a shared dotted canvas with differently sized artboards. The large campaign heading and draft/reference summary card are removed. A compact toolbar keeps size search, static/GIF filters and Add size; campaign controls remain on the right with their own scroll area. Click an artboard to edit it directly in Studio. Its selected layer's text, image source preview, crop/fade, styling and geometry controls appear in a contextual left panel labeled with the market and dimensions. The layer list collapses when a layer is selected. The panel header, undo and redo stay visible while scrolling. The small expand icon still opens the optional focused editor.

Inline edits validate and save a local override for only the selected banner automatically; shared copy, asset bindings, other banners and blueprint revisions are preserved. Local text changes always grow/shrink to fill the existing box while preserving its geometry. All text is retained: if saved minimum font size or row limits prevent fitting, the renderer adds rows and reduces font size below that preference, breaking overlong words at grapheme boundaries. The same fitter serves preview, PNG and GIF output. The shared inspector removes Layer name, Content binding and the manual Fill available space action; Text layout has no panel border/background. New text defaults to line spacing 1 and vertical middle. The workspace spacing migration also updates all current saved banner/blueprint text to 1 across markets, preserving geometry and historical snapshots. Image repositioning keeps the frame and fade fixed; Edit frame explicitly enables frame geometry. The selected artboard alone mounts the shared Konva editor, while other artboards use lightweight native-size previews. Source uploads and market typography remain in the shared campaign controls on the right. Selecting another banner switches the inspector and retains saved edits. Shared arrangement, reset and subject-placement results update the active inline editor. Its timeline appears below the canvas only for GIF output. On smaller screens, shared campaign controls hide while a banner is selected and return when deselected; narrow canvases place the inspector at the bottom.

Drag an artboard's dimension title to arrange whole boards on the Studio canvas; click it to select the banner. **Reset artboard positions** restores the automatic arrangement. These positions are per-market view state for the current Studio session, not saved artwork coordinates or persistent project data. Refreshing or leaving Studio restores the default arrangement.

The select, hand, zoom and fit controls live in a floating left rail, fixed to the canvas viewport. Selecting a banner frames it in the available space beside the inspector. In Select mode, artwork gestures manipulate layers; Hand or Space switches to camera panning. Selection handles keep a constant screen size as Studio zoom changes.

Canvas controls provide 10–300% zoom, reset to 100%, Fit all, select and hand tools. Drag empty space, hold Space while dragging, use the hand tool, or scroll to pan. Ctrl/Command + scroll zooms around the pointer (including trackpad pinch events). When the canvas itself is focused, +/− zoom, arrow keys pan and 0 fits all. All camera paths are bounded to the artboard collection and a small gutter; they cannot scroll endlessly into empty space. Bounds adapt to zoom, filters and viewport size. Fit mode adapts to viewport changes; manual camera changes stay in place while editing copy. New market/filter sets return to an overview. Camera transforms affect the view only: preview canvas buffers and exports retain their native dimensions. Mobile retains the canvas controls and places the campaign panel below the workspace.

The canvas action group is absolutely positioned at the top center inside the Studio viewport, outside the header and transformed artwork. It contains **Auto place subject**, **Match blueprints** and **Arrange now**. Match blueprints is a single toggle button, highlighted when **Keep blueprint boxes** is enabled. Clicking the inactive button applies the blueprint boxes and enables that setting; clicking it again disables the setting. Arrange now is a single toggle button for automatic arrangement, highlighted when active. Turning it on arranges immediately and keeps arranging future content changes; turning it off freezes automatic arrangement. Both toggles can be active together: blueprint boxes stay fixed while text fitting and subject crop adjust. Neither control contains a checkbox or a second click target. Settings and actions apply only to the selected market. The controls stay fixed while zooming/panning, wrap on smaller canvases, and lock during automatic subject placement. Fit all, the tool rail and selection inspector reserve space below the measured action height. The previous sidebar arrangement panel is removed. **Auto place subject** uses local Florence-2 and searches the uploaded image with the last submitted query, selects the preferred detection and applies a crop to every format in the active market. It runs once even with Auto arrange off, without changing that preference. It uses the latest current boxes, preserves frames/fades/text/timelines, and leaves original assets and blueprint revisions unchanged. A borderless infinite loading bar stays in the center of the artboard viewport, with just “Loading Florence-2…” and a small cancel icon. The loader stays centered in the viewport. The service does not report a completion percentage. Banner editing, shared campaign settings, uploads, arrangement, new sizes/markets, import and exports are locked during automatic placement, whether started by uploading an image with Auto find enabled or by the Auto place button. Canvas zoom, pan, wheel and keyboard controls are locked too; cancellation and read-only navigation stay available. Alternate Studio links and editor history respect the same lock. Completion, no matches, failure or cancellation unlock the canvas and editing. Upload placement waits for the uploaded image resources before cropping, including when Auto arrange is off. Re-uploading the same image starts a fresh attempt. No matches preserve the previous focus/crops; cancellation, image/query changes or manual focus selection discard pending results. The sidebar retains **Find subject**, query presets, detected-box selection and manual click/drag focus. Its manual choices follow the existing Auto arrange / Arrange now behavior.

## Common standard, market specialization

**Banner typography** is a per-market choice available in Studio and the editor. The bundled Outfit preset uses ExtraBold (800) for headline/CTA, SemiBold (600) for supporting/custom text and Regular (400) for legal. `src/core/typography.js` supplies the same font rule to text fitting, arrangement, quality review and the Canvas renderer, including GIFs. Outfit's Latin and extended Latin faces finish loading before resources become available to previews/exports. The original option retains saved layer weights and the market's uploaded font or Arial; uploading a custom font selects that option. Existing campaigns retain their original typography until explicitly changed. Blueprint snapshots are not rewritten by this campaign setting.

The market's logo is an original image asset you upload, independent of typography. Upload/replace it from the Studio sidebar or select a logo layer in the editor. SVG, PNG, JPEG and WebP are supported; it is contained inside the existing logo box without distortion. The binding is shared only across that market's formats. Existing editor layout and undo state stay mounted while replacement assets load; a neutral "LOGO" text placeholder (and its stacked control) appears only when no logo image is bound.

All Studio processing is scoped to the active market. Local Florence-2, uploaded-image bindings, shared copy, subject focus, automatic/manual arrangement, blueprint matching use only that market's campaign and banners. Having images in seven markets does not start seven searches. Editor and blueprint detail URLs resolve their market from the displayed entry, ahead of a missing or conflicting query string. Switching markets aborts the previous client search, discards late results and releases its editing lock; already-running server inference may still finish. The newly selected market can run its own search according to its saved Auto find setting. Original asset storage is shared and deduplicated, but campaign bindings and search results remain per market.

Size presets are shared. A factory seeds `portrait`, `rectangle` and `strip` arrangements from normalized proportions. A market/size receives its own complete JSON revision, so a BANNER2 300×250 can differ from BANNER1 300×250. A common-template change affects future seeds; it never mutates saved market revisions. User-added sizes remain drafts until individually reviewed.

Market data owns legal defaults and locale. Campaigns bind market-specific logo/font assets. There is no global legal string and no bundled legal copy: every market, including the starter markets, starts with an empty legal line and a quality warning.

## Version and override lifecycle

Blueprint revisions remain immutable in the stored project. The library displays a schematic of the active revision: logo, text, image, CTA and legal boxes, plus any saved fade curve. There is no bundled example artwork. Diagrams never bind live campaign text or uploads. **Add size → Create blueprint** creates the size and opens `/blueprints/:entryId/edit`; existing cards and detail pages offer **Edit blueprint**. The shared editor supports layer geometry/order/visibility, bound text boxes and alignment, image/logo/CTA/shape/text additions, background, fade curves and GIF timing. Save blueprint appends a draft revision and immediately synchronizes the matching Studio banner. Publishing remains unavailable.

`core/blueprint-edit.js` applies changed standard properties to that banner’s effective snapshot, preserving local copy, image focus/zoom and unrelated overrides. Added/removed/reordered standard layers and edited scene data also apply. Other markets/sizes, campaign bindings, original assets and old revisions remain intact. The old effective banner is retained in history before the updated snapshot; the banner pins the new revision. Its current layout key prevents a redundant automatic arrange pass immediately after saving. Later campaign changes still follow the existing automatic arrangement preference. Quick **Edit blueprint fade** uses the same save/sync path, restricted to image fade settings.

Previously saved mesh standards are adopted once for the active market, copying only fade properties and retaining local geometry, copy, crop and history. Optional `banner.syncedBlueprintVersionId` records this adoption, so later Studio-only fades survive reload. New saves set the same marker. `origin: "blueprint-editor"` on revisions distinguishes deliberately edited geometry from historical defaults; old centering corrections do not overwrite it. A subsequent fade-only save retains that origin.

In Studio, select the campaign image and choose **Fade shape → Mesh · editable points**. Sixteen draggable points shape the boundary; Straight, U shape and Arch presets provide starting curves, and softness controls the transition width. Done editing fade returns to photo repositioning. The same controls work in the focused editor, including rotated frames. Blueprint diagrams show the curve and softness guides, with draggable/keyboard-accessible points inside the dedicated fade dialog. Source images and text remain unchanged by a standard fade edit.

Studio banners pin revision IDs and update automatically when campaign content changes. Reset/regenerate a single banner explicitly removes that banner's override. Inline Studio changes append validated snapshots automatically; the focused editor retains its explicit Save banner action. Both use the same override history and shared rendering pipeline. Studio saves never modify the reference entry or its revisions.

**Match blueprints** applies the active market’s latest boxes and horizontal/vertical alignment to Studio, including older custom layouts. It preserves campaign copy and assets, per-format text, glow and other styling, photo treatment, and animation; changed overrides retain their earlier snapshots in history. The action enables **Keep blueprint boxes**. In that mode Auto arrange fits text through the shared renderer and adjusts only subject crop inside the saved frames. It does not resize or redistribute text/image boxes. Manual editor placement remains a banner-specific exception; Match blueprints can reapply the standard. Turning Match blueprints off restores flexible automatic arrangement. These choices persist with campaign backups.

Explicit standard corrections center the BANNER2 300×600 and 160×600 headline and subtitle boxes and text. Fresh seeds use it directly. On project load or backup restore, a differing unreferenced draft receives a new active revision, preserving every prior revision, working draft and pinned campaign snapshot. Referenced, published, manually edited blueprint standards, rotated and moving layouts are excluded. Rules live in `src/data/layout-corrections.js`; the diagram continues to draw the actual saved geometry.

## Animation

Studio displays each GIF as an outlined group: the main editable artboard is followed by a vertical column of all animation parts at the same native dimensions. Part names and durations label deterministic midpoint snapshots rendered with the shared timeline pipeline. Clicking a part selects its banner and seeks the main inline editor to that moment. Static formats remain single artboards. Group dragging moves the whole collection, and packing, Fit all and bounded panning account for the full group height. Part edits and GIF/static toggles update the column automatically; export dimensions are unchanged.

The editor shows its timeline and repeat control only when **Create GIF** is checked (`mode: animated`). Unchecking stops playback and returns to the first frame for static PNG/JPEG/WebP output. Parts and their timings remain stored, so re-enabling GIF restores them. A GIF may have one part.

Scene durations are milliseconds, rounded to GIF's 10 ms resolution when encoding. Cuts preserve the supplied reference delays. Fade transitions and per-layer fades are evaluated deterministically and sampled at 10 fps (with exact scene and track boundaries included). A new part can be added, renamed, moved or removed; each part has its own layer tracks. Repeat is stored as GIF repeat count, where 0 means infinite.

## Subject positioning

Uploads automatically find subjects with local Florence-2 phrase grounding using the installed CPU/CUDA profile. Florence-2 is the default detector; missing setup or failed inference shows an error and leaves manual focus available. SAM 3 is excluded from automatic search and Create. Its precision API remains opt-in. Search by object name (for example, playing card or trophy), choose a detected box, or mark a manual area on the source preview. Auto arrange uses the focus independently for each banner size. With Auto arrange off, the chosen focus is saved until Arrange now is pressed. The editor’s Focus on subject action reapplies it to the selected photo without moving the frame or fade.

Sidebar searches retain their nonblocking behavior; the explicit Auto place action temporarily locks editing and export until it finishes or is cancelled. Florence-2 runs in a loopback-only Python process; cancelled client results are discarded although active GPU work may finish in the background. Searches use local files only. Small, stylized or obscured subjects may be missed; a no-match result retains any existing focus and allows manual selection. Tight frames can still clip or cover subjects and produce a review note. Cropping uses subject boxes; optional image tools separately support cut-outs without making them a requirement for normal rendering.

## Persistence and portability

Original uploads remain immutable in IndexedDB, deduplicated by SHA-256. Browser storage can be cleared or evicted; Export project produces a ZIP containing project JSON and original uploaded assets. Import validates before replacing local project state. Store failures are surfaced; the interface does not claim a successful save when persistence fails.

## Quality and readiness

Before export inspect source resolution, fallback font/logo, a missing campaign image, missing legal copy, text overflow, layer bounds and total animation duration. Exports from draft templates include DRAFT in filenames and the manifest. Draft export is useful for review, not a representation of legal/brand approval. File sizes are measured after encoding; platform-specific caps require platform configuration in a later increment.

## Technology decisions and sources

Konva is a mature Canvas 2D interaction layer appropriate to these small 2D banners. WebGL is not necessary for the first renderer; a future renderer adapter can consume the same JSON. Preview and export use a shared draw pipeline to avoid DOM screenshot differences. See [Konva export documentation](https://konvajs.org/docs/react/Canvas_Export.html), [Vite setup](https://vite.dev/guide/), and [OpenCV.js usage](https://docs.opencv.org/4.13.0/d0/d84/tutorial_js_usage.html).

Versions were checked against the npm registry on 27 September 2026 and pinned in the lockfile. `@techstark/opencv-js` supplies the local browser runtime; it loads only for image analysis. AI segmentation is deferred behind a capability adapter; it is not a dependency of this system.

Bottom legal text has its own background footer. `src/core/legal-footer.js` shortens a stationary image frame before the bottom legal box (4 native pixels of clearance, 2 on formats up to 100 px high). The same constraint is used by blueprint diagrams, resolved campaign snapshots, automatic arrangement, the editor and rendering/export. Legal text, its box, image crop controls, fade and timings stay intact. Legacy draft standards receive an appended revision, including measured drafts; earlier revisions remain preserved. Existing campaign snapshots resolve with footer clearance without rewriting their history. Rotated/moving frames and separate legal-only GIF parts retain their custom geometry.

## Banner 3 market

`src/data/banner3.js` holds the Banner 3 layout table: 11 sizes (nine GIFs, two static) with native-pixel logo, headline, subtitle, CTA, image and legal boxes, the GIF part sequence (headline, offer, then CTA or legal) and 2000 ms part durations. Each part remains editable through the shared timeline. Banner 3 campaigns default to Outfit typography and Match blueprints. Missing sizes are added to existing workspaces without touching saved work. There is no bundled artwork: the image and logo come only from campaign uploads.

## Legacy workspace migration

`src/core/legacy-migration.js` runs before validation on load and backup import. Workspaces saved before 28 October 2026 used an older ID and name for the Banner 3 market, bundled example links and brand starter copy. The migration renames that market to `BANNER3`/`Banner 3`, drops `reference`/`references` links (marking those entries `measured`), `resourcePreset` and `referencePack`, and resets campaign copy and legal lines only while they still equal the old shipped defaults. It also renames old Banner 3 GIF parts named after a casino offer to Headline/Offer, removes the old operator licence number from any legal line, and drops approved shorter copy whose field was reset or still holds the starter placeholder. Other copy the user changed is kept. Current workspaces pass through unchanged.

## Strict generation and intelligence extension

`src/core/generation/` holds the Create workflow: `flow.js` (typed node ports Image/Copy/Analyze/Qwen layout/Format, validation, the load-time migration that removes the old Compose node), `batch.js` (frozen snapshot, `generateBatch`, accept, undo, export), `prepare.js` (Florence-2 / PaddleOCR / OpenCV evidence), `cutout.js` (optional BiRefNet), `planner.js` (service client and Qwen shorter copy), the intelligence store, search, fingerprints and media import. Layout choice reuses `src/core/ai-arrange.js` (`layoutTarget`, `candidateLayouts`, `chooseLayout`, `seedBlueprint`), the same code as Studio's Arrange now.

Open **Create** for a connected draft-generation graph: **Image → Analyze image → Qwen layout → Format nodes**, with **Copy** also connected to Qwen layout. There is no Compose node and no blocking checker.

- **Image** uploads or replaces the active market's source; **Copy** edits the market's exact headline, subtitle, CTA, legal copy and creative brief.
- **Analyze image** runs Florence-2 (objects, main subject), PaddleOCR (text printed in the photo) and OpenCV (colour); a BiRefNet cut-out is optional. A missing model is reported and the run continues.
- **Qwen layout** (Qwen3-VL 8B, text-only PosterO method, `/vision/layout`) places every connected format using the market's nearest measured blueprints as in-context examples. For each size the code then compares the saved design, the nearest measured blueprint scaled to that size and Qwen's layouts with the same scoring as Studio's Arrange now (fit, collisions, subject crop, reading order, closeness to the reference) and keeps the best. Text fits inside its box and the photo crop follows the subject: every size produces a draft. Turning Qwen off, or Qwen being unavailable, still produces drafts from the saved design or nearest reference.
- **Format** nodes show the draft, which candidate won and any copy that is too long for that size. **Suggest shorter …** asks Qwen for shorter copy; an approved version applies to that size only (`campaign.copyFits`). Generate one size only, Download PNG, Use in Studio (a local edit on that banner, undoable) and Edit in Studio. The Qwen layout node holds Generate layouts, Use all drafts in Studio, Export generated drafts / market matrix, Undo generation and Cancel.

Saved flows from before this change (with a Compose node) are migrated when the project loads; batches from the old strict engine are dropped as regenerable history. Banners already accepted from the old engine keep rendering unchanged.

A batch snapshot freezes the campaign (without Studio-only state), each target's base design (the pinned saved revision, or a new size seeded from the nearest measured blueprint with stable part ids), its nearest measured designs and the engine id `qwen-layout-1`. Studio arrangement or local edits therefore never make a fresh draft stale; copy, image, market or saved-blueprint changes do. Accepting stores the draft as a local override with history; master revisions stay unchanged. Previews and exports use the shared renderer. `strict-v1` text fitting is kept only so banners accepted from the removed engine still render and export identically; new drafts do not use it.
