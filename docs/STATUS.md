## Evidence and limitations

No example banners, hero photography, brand logo or production font ship with the app. Starter layouts are drafts, not reproductions or approved templates. The "LOGO" text placeholder and Arial fallback are draft stand-ins. Every market's legal line starts empty. Stored publication metadata does not imply legal/regulatory approval.

These templates reproduce broad layout rules, not exact reference pixels. Red text glow is now available as an editable effect. The rising-arrow offer asset and exact brand typography still need production assets. Reference image files are evidence; current rendered snapshots cannot be called approved golden masters.

The editor is desktop-oriented (minimum 920 px wide). The campaign review interface adapts to mobile. GIF export is synchronous per sampled frame with event-loop yields, at 10 fps for animated effects; it is bounded to 120 million sampled pixels. Static/cut GIF timing matches the supplied files. No worker/server encoder or animated WebP yet. Finite GIF repeat applies to export; editing playback always cycles.

Images support opaque-background fades, cover crop, direct panning and opacity. Text supports glow and geometry-based space suggestions. Local Florence-2 detection and manual region selection guide smart crops. Detection can miss small/stylized subjects; a fixed cover frame cannot always preserve the whole subject or avoid every overlay. Review flagged crops. Florence-2 now proposes OCR text boxes from an uploaded finished banner, but full automatic reference-layout reconstruction and role recognition are not implemented. Arbitrary masks and blend modes remain incomplete; later image-tool work provides separate cutout/upscale/extension paths. OpenCV analyzes imagery; it does not infer legal or brand compliance.

The shared local Python service uses pinned Transformers with CPU/CUDA profiles. Qwen3-VL 8B, Florence-2 and BiRefNet are installed on this Windows machine. Default workflows do not require SAM authentication or weights; missing gated SAM files affect only an explicit precision request. Earlier Linux SAM timing/accuracy checks remain historical evidence, not claims about the current detector. The current Florence and BiRefNet checks are recorded in the latest entry below. Production-image quality still needs review; normal rendering and manual focus remain available without AI.

Existing version history is retained in project data; the blueprint library does not edit or roll back versions. There is no multi-user account, cloud sync, deployment, campaign-history browser or permission system. One active campaign per market is supported. Browser storage can be evicted; use workspace backups. Asset-level delete/reuse management and per-platform file-size rules remain future work; configurable size targets drive PNG/JPEG/WebP quality steps and GIF colour/frame reduction.

### 27 October 2026: Fit-first generation instead of blocked sizes

A size that does not fit is now adapted before it is reported as blocked, in this order:
1. The normal layout search (campaign minimum font, default 14px).
2. Smaller text: the minimum drops to `fallbackMinimumFont` (default 12px).
3. The subtitle is left out, unless the policy lists it as a required role.
4. Shorter copy for that size only: Qwen's suggestions when it is ready, plus the copy's own leading whole words. The result is `needs_approval`: previewed, but not accepted into Studio or exported until the user approves the text, which stores it in `copyFits` for that size.
5. The last resort, `lastResortMinimumFont` (default 10px), with the full copy, then with shorter copy.

Legal copy is never shortened or left out. Saved-Blueprint runs that keep boxes, and locked layers, are never adapted. Each result records its `adaptation` (minimum font, omitted roles, proposed copy and whether Qwen or the leading words produced it), shown on the review card and Format node. Export re-checks a scene against that same adaptation. The strip layout's CTA is now sized to its text (up to half the copy width); before, it was capped near a quarter of the copy width and long CTAs such as "Rekisteröidy" could not fit. Solver version is `strict-layout-7`.

Verified in a browser with the BANNER1 copy: 728×90, 300×250, 160×600 and 1080×1920 now fit (160×600 via 12px text). 320×50 still blocks: the 50-character BANNER1 legal line needs most of the strip at the 9px legal minimum, and legal is never shortened. The visual quality of 10–12px strip layouts has not been reviewed against references.

### 27 October 2026: AI Arrange now in Studio (hybrid, PosterO-style Qwen layouts)

Studio **Arrange now** is now a one-time AI arrangement; the new **Auto: On/Off** toggle owns automatic refits after copy or image changes.

1. The rendered campaign photo is analyzed once and saved as `campaign.photoAnalysis`: OpenCV brightness/detail grid, BiRefNet subject map (`POST /tools/saliency`), PaddleOCR text printed in the photo and Florence-2 objects. Missing models are listed in the result; OpenCV always runs.
2. Qwen3-VL (text-only, `POST /vision/layout`) proposes layouts per size with a re-implementation of the PosterO method (CVPR 2025): SVG layout trees, the four nearest references as in-context examples, three seeded samples.
3. For every banner the saved design, the nearest reference scaled to the size and every Qwen proposal (also with the reference's photo frame) are finished by the same arrangement and scored with the same checks (fit, collisions, subject crop, photo readability, closeness to the nearest reference). The cheapest is kept as `banner.aiLayout`; automatic passes refit copy from it. Manually edited banners and Match blueprints are left alone.
4. **Copy fit** lists sizes whose copy cannot fit at its minimum size; Qwen3-VL suggests shorter versions and an approved one applies to that size only (`campaign.copyFits`, now honoured in Studio as well as Create).
5. Blueprint import asks Qwen3-VL (`POST /vision/roles`) for each OCR line's role; the rule-based roles are the fallback.
6. New sizes and new markets are seeded from the nearest reference shape instead of the proportional factory (which remains for the built-in seeds and when no reference exists). The old luminance-only "Analyze source image" panel is replaced by **Photo analysis**.
